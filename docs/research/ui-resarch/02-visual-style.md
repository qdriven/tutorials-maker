# 02 · 视觉风格建议

> 目标：一眼看出“这是人编的”，而不是“这是 AI 生成的”。

## 0. 判断标准

给这个产品选风格，不看“今年流行什么”，先看它要同时满足什么：

| 需求 | 对风格的约束 |
|---|---|
| 人工策展的可信度 | 不能太潮、太花、太像模板；要有编辑感、纸感、时间感 |
| 大量文字 + 元数据 | 排版必须稳，信息层级必须清楚，不能靠图标和颜色救场 |
| 教育 / 学习语境 | 温度、耐心、可读性；不能太冷、太攻击性 |
| 资源类型混杂（课程/文章/视频/工具） | 容器要克制，让内容本身产生差异，而不是给每类内容一套花哨卡片 |
| 长期维护 | tokens 要少、组件要稳、风格要耐看；不能三个月就过时 |
| 用 AI 生成页面 | 规范必须能写成 `DESIGN.md`，让 AI 有明确约束 |

## 1. 三个方向对比

| 方向 | 关键词 | 优势 | 风险 | 适合 |
|---|---|---|---|---|
| **A. 编辑式暖极简**（推荐） | 暖纸、墨色、衬线标题、1px 细线、编号、单一朱砂色 | 可信、耐看、内容优先、和“人工策展”天然契合；容易做出差异 | 需要排版纪律和真实素材；做得不好会显得寡淡 | 全站基座 |
| **B. 瑞士网格 / 新粗野主义** | 大黑体、硬网格、黑白 + 信号色、可见边框 | 识别强、现代、结构清楚；适合封面和专题 | 偏冷、偏攻击性；容易撞型；教育语境下可能显得不友好 | 首页主视觉、合集封面、活动页 |
| **C. 暗色电影感** | 黑底、大图、金色、慢动效 | 沉浸、高级；适合视频课程 | 长文阅读疲劳；内容密度难做；成本和素材要求高；暗色 SaaS 已经泛滥 | 单个视频课程 / 媒体 hero，不做全站 |

**推荐组合：A 作为全站基座，借 B 的网格纪律，C 只在“本期专题”或视频 hero 局部使用。**

原因：

- 这个产品的核心资产是“编辑的判断”，不是“课程视频的制作水准”。暖极简比暗色电影感更适合承载文字和元数据。
- 资料库需要高密度扫读。暗色 + 大图会让每个资源都变成“海报”，反而降低比较效率。
- 瑞士网格的结构感可以保留，但不要用纯黑 + 荧光色 + 巨粗黑体，那会走向另一个 AI 默认（“设计感”模板）。
- 暖纸色 + 衬线 + 细线，是教育、出版、文化类产品最稳的组合；它不靠流行色，靠比例和细节。

## 2. 推荐方向：编辑式暖极简（Editorial Warmth）

一句话：

> 像一本认真编过的课程目录：纸色底、墨色字、宋体/衬线标题、细线分栏、编号索引，只有一点朱砂色用来标记“编辑的选择”。

### 六个原则

1. **内容先于容器。** 先用排版建立层级，再考虑要不要加边框/背景；大多数内容不需要卡片。
2. **纸与墨。** 背景是暖白纸，文字是近黑墨；不用纯白 `#FFFFFF` 和纯黑 `#000000`。
3. **一个记忆点。** 全站只保留一个高饱和强调色（朱砂），用在小面积：链接 hover（文字用 `accent-strong`）、编辑注竖线、选中态、关键 CTA。
4. **细线优先。** 用 1px 线、留白、编号划分区域；不用阴影、不用毛玻璃、不用大圆角。
5. **真实素材。** 真截图、真封面、真来源；没有图就用排版封面（编号 + 模块名 + 纸色底），不要 AI 插画。
6. **克制。** 动效只做反馈；装饰只做层级；每个页面只允许一个“视觉事件”。

## 3. 三个视觉签名

这三个东西要贯穿全站，成为“一看就知道是这里”的元素。

### 3.1 编号系统

- 模块：`M-01`、`M-02`
- 合集：`ISSUE 03`
- 资源：`R-041`
- 课程章节：`01 / 02 / 03`

用法：

- 等宽字体、12px、字距 `0.08em`、颜色 `muted`。
- 出现在列表行首、详情页面包屑、合集封面、页脚。
- 编号是稳定的，不随排序变化；用户可以用编号引用一个资源。

### 3.2 编辑注

- 每条资源详情都有“为什么收录”，2–4 句，衬线体，左侧 2px 朱砂竖线，背景 `paper-2`。
- 合集页有“编辑的话”，2–3 段，说明选编逻辑。
- 语气像人写的，不像营销文案；可以写“这篇有点长，但第 3 节值得”，不要写“本课程将赋能你……”。

### 3.3 索引视图 / 画廊视图

- 资料库默认“索引视图”：纯文字行，编号、标题、格式、难度、时长、日期。
- 可切换“画廊视图”：3:2 缩略图卡片。
- 这个切换本身就是产品态度：我们相信文字索引，但也给你视觉浏览的选择。

| `--ink` | `#1A1915` | 标题、正文 | 与 paper 16.3:1 |

**暗色（可选）**

| Token | Hex | 用途 |
|---|---|---|
| `--paper` | `#161512` | 页面底色（暖黑，不是纯黑） |
| `--paper-2` | `#1D1B17` | 卡片 / 悬浮 |
| `--ink` | `#EFE9DC` | 标题、正文 |
| `--ink-2` | `#C9C1B1` | 次级正文 |
| `--muted` | `#9C9382` | 元数据 |
| `--line` | `#34302A` | 分隔线 |
| `--line-ui` | `#6B6457` | 控件边界（3.2:1） |
| `--accent` | `#E07252` | 强调色（与暖黑 5.9:1） |
| `--accent-strong` | `#E07252` | 主按钮底色（按钮上用深色字） |
| `--accent-soft` | `#3A241E` | 编辑注背景 |
| `--green` | `#8FB39F` | 完成状态 |
| `--gold` | `#D8A84E` | 新收录标记 |

**使用比例：**

- 70% 纸色 / 背景
- 20% 墨色 / 文字
- 8% 灰调 / 次级信息与线
- 2% 朱砂 / 强调

**规则：**

- 朱砂不用于大面积背景；一块区域最多一个朱砂元素。
- 小字、链接 hover、TOC 当前项用 `--accent-strong`（#A13A22）；`--accent`（#C2482B）只用于装饰线和色块。
- 难度、格式、价格不要用红黄绿交通灯；用文字 + 小圆点表示，颜色只是辅助。
- 暗色模式不是默认；如果做，必须保证和亮色同样的对比度和层级，不能只是把颜色反过来。

### 4.2 字体

| 用途 | 字体 | 回退 | 说明 |
|---|---|---|---|
| 展示标题 | **Newsreader**（拉丁）+ **Noto Serif SC / 思源宋体**（中文） | `Songti SC`, `STSong`, serif | 编辑感、文化感；不要用 700/800 |
| 正文 / UI | **IBM Plex Sans**（拉丁）+ **Noto Sans SC / 思源黑体**（中文） | `PingFang SC`, `Microsoft YaHei`, sans-serif | 比 Inter 更有性格，和等宽字体同源 |
| 等宽 / 编号 | **IBM Plex Mono** | `SFMono-Regular`, `Consolas`, monospace | 编号、日期、统计数字，开启 tabular numerals |
| 引文 / 编辑注（可选） | **LXGW WenKai / 霞鹜文楷** | 回退到 Noto Serif SC | 只用于短引文，不要用于长正文 |

**为什么不用 Inter / Geist：**

它们没有错，但已经是 AI 生成页面的“默认字体”。这个产品需要一点编辑气质，Newsreader + IBM Plex 的组合更有出版物感，也更不容易“一眼 AI”。

**中文字体加载：**

- 中文字体文件很大（完整字重通常 5–15MB），不要全量加载。
- 只给 H1/H2 加载 `Noto Serif SC` 的 500 字重，并按 `unicode-range` 子集化；正文中文用系统字体栈。
- 如果标题用字无法提前子集化，回退到系统宋体（`Songti SC` / `STSong`），不要让 10MB 中文字体阻塞首屏。
- `font-display: swap`；预加载展示字体，避免首屏标题闪烁。
- 不要用 `font-weight: 700` 渲染中文；浏览器会伪粗体，笔画会糊。用 500/600 + 字号/间距建立层级。

### 4.3 字号与行高

| Token | 字体 | 字号 | 行高 | 字重 | 字距 | 用途 |
|---|---|---|---|---|---|---|
| `display` | Serif | `clamp(44px, 6vw, 84px)` | 1.02 | 500 | -0.02em | 首页主张、合集刊头 |
| `h1` | Serif | `clamp(36px, 4vw, 56px)` | 1.10 | 500 | -0.01em | 页面主标题 |
| `h2` | Serif | `clamp(28px, 2.6vw, 40px)` | 1.15 | 500 | 0 | 区块标题 |
| `h3` | Serif / Sans | 28px | 1.25 | 500 | 0 | 小节标题 |
| `h4` | Sans | 20px | 1.35 | 500 | 0 | 卡片标题、列表分组 |
| `lead` | Sans | 20px | 1.60 | 400 | 0 | Hero 副文、合集 dek |
| `body` | Sans | 17px | 1.75（中文 1.8） | 400 | 中文 0.01em | 正文 |
| `small` | Sans | 14px | 1.60 | 400 | 0 | 元数据、说明 |
| `micro` | Mono | 12px | 1.50 | 500 | 0.08em（仅拉丁大写） | 编号、眉题、标签 |
| `number` | Mono | 13px | 1.40 | 400 | tabular | 日期、计数、时长 |

**中文排版规则：**

- 正文每行 30–40 个汉字（约 62–68 个拉丁字符），最大宽度 720px。
- 行高 1.75–1.8；段间距 1em；不要首行缩进，不要两端对齐。
- 标题用 `text-wrap: balance`，正文用 `text-wrap: pretty`（支持的浏览器）。
- 中英文混排时，中英文之间不要手动加空格；用 `text-autospace` 或依赖浏览器。
- 标点不要出现在行首（避头尾），CSS 可用 `line-break: strict`；重要文案人工检查。
- 不要用全大写英文给中文做“标签”；中文标签保持正常大小写。

### 4.4 间距

- 基础单位：4px。
- 间距序列：`4, 8, 12, 16, 20, 24, 32, 40, 48, 64, 80, 96, 128`。
- 区块垂直间距：桌面 96px / 平板 64px / 手机 48px。
- 组件内间距：卡片 20–24px；按钮左右 20px；列表行上下 16px。
- 标题与正文：H2 下方 16–20px；H3 下方 12px；正文段落之间 1em。
- 不要用 `margin-top` 和 `margin-bottom` 同时堆叠；统一用 `gap` 或单向 margin。

### 4.5 圆角、边框、阴影

| 元素 | 值 |
|---|---|
| 图片 / 卡片 / 按钮 / 输入框 | **2px** |
| 标签 / chips | **2px**（矩形，不是胶囊） |
| 表格行 / 分隔线 | **0** |
| 状态圆点 | 50% |
| 阴影 | **无** |

- 全站不用投影；需要层级时用 1px 线、背景色差、间距。
- 吸顶导航只用底部 1px 线，不用阴影。
- 弹层用实色 `paper` + 1px `line-ui` + 半透明遮罩（不加 `backdrop-filter`）。
- 大圆角（16–24px）+ 投影是“AI 卡片”的最大特征，明确禁止。

### 4.6 动效

- 时长：hover 160ms；面板 / 抽屉 220ms；页面切换不做。
- 缓动：`cubic-bezier(0.2, 0, 0, 1)`（ease-out）。
- 只做反馈：链接下划线、按钮底色、箭头位移 2px、图片轻微透明度变化。
- 不做：滚动视差、滚动触发动画、自动轮播、鼠标跟随、背景粒子。
- 必须尊重 `prefers-reduced-motion: reduce`：关闭所有非必要动画。

### 4.7 图标与图像

- 图标：Phosphor Icons（Regular / Light）或 Lucide，1.5px 描边，18/20/24px；全站只用一个图标集。
- 不用 emoji 当图标；不用彩色 3D 图标。
- 图片比例：资源卡 3:2；合集封面 4:5；课程 hero 16:9；头像 1:1。
- 图片统一 1px 边框、2px 圆角、`object-fit: cover`；不加阴影、不加倾斜、不加贴纸。
- 没有图片时用“排版封面”：纸色底 + 编号 + 模块名 + 一句标题；不要用渐变占位图。
- 不用 AI 生成插画、3D 球、抽象渐变；用真实截图、书封、课程封面，并注明来源。

## 6. 页面级应用

| 页面 | 视觉重点 | 克制的地方 |
|---|---|---|
| 首页 | 一个衬线大标题 + 一张本期封面 | 不堆卡片、不放产品截图、不放三个图标功能 |
| 资料库 | 密排索引行 + 细线 | 不用缩略图（索引视图）、不用彩色标签 |
| 合集 | 刊头 + 编辑注 + 目录 | 只放一张封面；不再加第二张 hero |
| 资源详情 | 标题 + 编辑注 + 外链 | 侧栏元数据用文字，不用徽章墙 |
| 课程阅读 | 正文排版 + 目录 + 进度 | 没有装饰性 hero；没有背景图 |
| 收藏 | 简单列表 | 不做 dashboard 式统计卡 |

## 7. 反 AI 味清单

| 常见 AI 默认 | 本项目做法 |
|---|---|
| 蓝紫渐变 / 霓虹光晕 | 暖纸色 + 墨色 + 单一朱砂 |
| 玻璃拟态 / 毛玻璃 | 实色背景 + 1px 细线 |
| 大圆角卡片 + 投影 | 2px 圆角 + 无阴影 + 细线 |
| 等大 bento 网格 | 编号索引列表；非对称只用于主次 |
| Inter / Geist + 居中大标题 | Newsreader + IBM Plex；左对齐编辑式 |
| 每个标题前一个 icon | 文字层级 + 编号；图标只用于操作 |
| 假数据 / 假 logo / 假评价 | 真实收录数、来源、日期；没有就不放 |
| 夸张的滚动动效 | 160–220ms 反馈动效；尊重减少动效 |
| AI 插画 / 3D 球 / 抽象渐变 | 真实截图、封面、排版封面 |
| 全站暗色 + 荧光绿 | 亮色纸感为主；暗色可选且暖黑 |
| 每个资源都做成“海报卡” | 资料库默认文字索引，画廊视图可选 |
| 满屏 pill 按钮 | 2px 矩形；只有状态点用圆形 |

**给 AI 的硬约束：**

> 不要引入 `DESIGN.md` 之外的字体、颜色、圆角、阴影和动效。不要用渐变、毛玻璃、大圆角卡片、等大 bento、图标堆砌。先读 `DESIGN.md`，再写代码。

## 8. 可访问性与性能

**可访问性（目标 WCAG 2.2 AA）：**

- 正文对比度 ≥ 4.5:1；大字 ≥ 3:1；控件边界 ≥ 3:1。
- 焦点环：2px `--accent-strong`，offset 2px；不要 `outline: none`。
- 所有交互可键盘完成；提供“跳到主要内容”链接。
- 触摸目标 ≥ 44×44px；相邻链接间距 ≥ 8px。
- 图片有 alt；装饰图 `alt=""`；视频有字幕/文字稿。
- 不要只用颜色表达状态（难度、完成、错误都要有文字）。
- 支持 `prefers-reduced-motion`、`prefers-color-scheme`、200% 缩放。
- 中文正文不要两端对齐；不要用 12px 以下的正文字号。

**性能目标：**

- LCP < 2.5s，INP < 200ms，CLS < 0.1（移动端 4G 基准）。
- 中文字体子集化 + `font-display: swap`；首屏只预加载一个展示字体。
- 图片用 `srcset` + `loading="lazy"` + `width/height` 或 `aspect-ratio`。
- 不引入重型动画库；CSS transition 足够。
- 列表页服务端渲染；筛选可以用客户端增强，但首屏必须有内容。

## 9. 落地顺序

1. 先落地颜色、字体、间距、圆角这四组 token，写进 CSS 变量。
2. 做 `Header` / `Footer` / `Button` / `Tag` / `ResourceRow` 五个基础组件。
3. 用资料库列表页做第一张“风格校准页”；所有后续页面以它为准。
4. 再做合集页和资源详情，验证编辑注、封面、元数据。
5. 最后做首页主视觉；这时你已经有真实内容和组件，不会做成空壳。
6. 把最终 token 和组件规则同步进 `DESIGN.md`。
