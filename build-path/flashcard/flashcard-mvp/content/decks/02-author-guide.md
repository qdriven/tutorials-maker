# 一个文件就是一套卡组

在 `content/decks/` 下新建一个 `.md` 文件，这套卡组就出现在左边目录里，不用改任何代码。

文件开头的 frontmatter 写元数据。

---

# frontmatter 字段

```yaml
---
id: my-deck
title: 我的卡组
summary: 一句话说明
group: 分组名
minutes: 5
---
```

- `id` —— URL 定位用的稳定标识，别随便改
- `title` —— 侧栏目录和移动端胶囊里显示的名字
- `summary` / `group` / `minutes` —— 辅助信息，可省

---

# 用 `---` 分卡

正文里每个单独一行的 `---` 把内容切成两张卡。卡内是标准 markdown：标题、列表、代码块、表格都支持。

你现在看到的这一张，就是 `---` 之后的内容。

---

# 交互卡：`:::quiz` 测验卡（语法）

````
:::quiz
question: 题干写在这里
answer: 0
- 选项一 :: 选这个时显示的反驳
- 选项二
:::
````

---

# quiz 的行为

答错会显示**该选项专属**的反驳——`::` 后面那句话就是为这个选项写的。

答对的卡会被记住（localStorage），侧栏里对应的行会打勾。

---

:::quiz{title="测验：加卡组要改代码吗"}
question: 新增一套卡组需要改代码吗？
answer: 1
- 需要，要在路由里登记 :: 不需要。内容目录在构建时自动扫描，丢文件进去就行。
- 不需要，往 content/decks/ 丢一个 md 文件就行
:::

---

# 交互卡：`:::flip` 翻面卡（语法）

````
:::flip
front: 以为：……
back: 其实：……
:::
````

点击卡片翻面，适合写「容易想错的地方」。两面各写一句话。

---

:::flip{title="翻面：`---` 到底是什么"}
front: 以为：正文里的 `---` 只是个装饰性的分隔线
back: 其实：它是 markdown 的 thematicBreak，解析器就是按它一张张切卡的
:::

---

# 参考栏：`:::ref`

在这张卡里加一个 `:::ref` 块，卡翻到它时，下方就会动画展开一条参考信息：

````
:::ref
源码对照：`demo/mini-harness/loop.ts · runTurn()`
:::
````

没写 `:::ref` 的卡，下方什么都不显示——参考栏是逐卡的事件，不是常驻占位。

---

# 想加新的卡类型？

卡类型 → 渲染组件是一张注册表（`src/components/cards/registry.ts`）。

新增一种内容 = 写一个组件 + 登记一行。没注册的类型会回落成普通 markdown 卡，不会白屏。
