# 第 07 章 · 把重复清洗变成可刷新的步骤

> 清洗步骤每做一次都是重复劳动：Power Query 把"连接 → 转换 → 合并 → 加载 → 刷新"固化成一条可复现的流水线。

- **ID**：`basics-ch7`　**短标题**：Power Query
- **学习目标**：理解连接、转换、合并、加载与刷新，知道查询编辑器与 M 语言的位置。
- **核心概念**：Power Query、Query Editor、M Language、Advanced Power Query

> 本章为 Excel 桌面功能导览；网页演示用公式复现合并逻辑，不冒充 Power Query 引擎。

## 🎯 本课重点

- **重点用什么**：数据 → 获取数据 → 自文件 的连接路径、主页 → 合并查询 → 合并为新查询 的合并路径，以及"合并键（SKU）必须唯一"这个前提。
- **完成什么**：能在自己的订单与商品两张表之间完成一次合并，补全单价并算出订单金额，并说清合并前为什么要先检查键的唯一性。

## 📦 配套数据

| 数据 | 文件 | 规模 | 用途 |
| --- | --- | --- | --- |
| 待补全订单 | [orders.csv](../data/lessons/power-query/orders.csv) | 3 行 × 5 列 | 合并的左表：只有 SKU 与数量 |
| 商品主数据 | [products.csv](../data/lessons/power-query/products.csv) | 5 行 × 5 列 | 合并的右表：SKU、商品、类别、单价、库存 |

数据说明：用公式复现 Power Query 的合并思路；教学模型，不是 Power Query 本身。订单表列头为 `订单号,SKU,数量,单价,销售额`，3 条记录（SO-1001/P-101/8、SO-1002/P-103/4、SO-1003/P-102/3），其中 `单价` 与 `销售额` 两列是空的，要靠合并补全。商品表列头为 `SKU,商品,类别,单价,库存`，5 条记录（P-101 冷萃咖啡 饮品 120 36；P-102 精品茶 饮品 80 58；P-103 咖啡豆 原料 200 24；P-104 保温杯 周边 150 42；P-105 手冲壶 器具 260 12）。

## 🧱 基础操作

1. **五步流程**：连接（数据来源）→ 转换（清洗与塑形）→ 合并（把多张表接起来）→ 加载（结果送回工作簿）→ 刷新（源变了重新跑一遍）。
2. **查询编辑器在哪**：Power Query Editor 是做转换的地方——删除列、替换值、拆分列、设置数据类型、透视与分组；它在加载与合并时被打开，但转换逻辑属于查询，不属于某张工作表。
3. **M 语言在哪**：在"高级编辑器"里查看或编辑 M 代码，是查询的底层表达；日常用界面操作即可，遇到界面做不到的转换才需要动 M。
4. **合并的三个前提**：选对合并键、确认键在右表唯一、明确连接类型（左外连接保留左表全部行，补不上的列为空）。
5. **自定义列 vs 静态结果**：在查询里加的计算列会随源数据自动更新；把算好的数字粘成静态值，就退回了手工维护。

## 🛠 实战操作

1. **先确认合并键唯一**：打开 [products.csv](../data/lessons/power-query/products.csv)，5 个 SKU（P-101…P-105）互不相同——这是能安全合并的前提。再看 [orders.csv](../data/lessons/power-query/orders.csv)，3 行的 SKU（P-101、P-103、P-102）都能在右表里找到，没有匹配不上的行。
2. **桌面版的连接与合并**：Excel 桌面版里走 数据 → 获取数据 → 自文件 → 选 `orders.csv` → 加载；再在"主页"里点 合并查询 → 合并为新查询 → 左表选订单、右表选商品表 → 用 `SKU` 列做连接 → 选择左外连接（左表全部保留）→ 展开右侧列（商品、类别、单价）→ 关闭并上载至工作表。
3. **网页版用公式复现同一件事**：在订单表 D2 写 `=XLOOKUP(B2,商品表!$A$2:$A$6,商品表!$D$2:$D$6,"未匹配")` → **120**；在 E2 写 `=C2*D2` → **960**。查找值在 B2，商品表 A 列是合并键，D 列是要带回的单价。
4. **把三行都算出来**：向下填充后得到下面这张表——合并补全了单价，自定义列算出销售额，合计 **2,000**（`=SUM(E2:E4)`）。

| 订单号 | SKU | 数量 | 单价（合并补全） | 销售额（计算列） | 商品 | 类别 |
| --- | --- | --- | --- | --- | --- | --- |
| SO-1001 | P-101 | 8 | 120 | 960 | 冷萃咖啡 | 饮品 |
| SO-1002 | P-103 | 4 | 200 | 800 | 咖啡豆 | 原料 |
| SO-1003 | P-102 | 3 | 80 | 240 | 精品茶 | 饮品 |
| 合计 | — | 15 | — | 2,000 | — | — |

5. **加一条有效性校验**：在 F1 写"有效标记"，F2 写 `=IF(OR(C2<=0,D2<=0),0,1)` → **1**，即数量与单价都为正才算有效行。合并之后补的列可能为空或为 0，这一步就是拦住它们的地方。
6. **说清"刷新"这件事**：桌面版里源 CSV 变了要回到查询点"全部刷新"；公式版改完源表自动重算——所以公式复现的只是合并逻辑与结果，不是 Power Query 引擎。
7. **记住合并前的那一步**：如果商品表里同一个 SKU 出现两行，合并会得到重复行，金额直接翻倍——合并前先对键做一次计数检查，比事后核对总数省事。

## ✅ 总结

- Power Query 的五步是连接 → 转换 → 合并 → 加载 → 刷新；转换在查询编辑器里做，M 语言在高级编辑器里。
- 合并的前提是键唯一：`SKU` 在商品表中 5 个值互不相同，订单表 3 个 SKU 都能匹配上。
- 合并结果：单价补全为 120／200／80，销售额 960＋800＋240 = 2,000。
- 网页版用 `XLOOKUP`＋`=C2*D2` 复现合并逻辑，用 `=IF(OR(C2<=0,D2<=0),0,1)` 拦截无效行，不冒充 Power Query 引擎。
