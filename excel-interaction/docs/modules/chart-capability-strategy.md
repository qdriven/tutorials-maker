# Excel 能力扩展的解决模式 + 「数据到图表」自动化分析

> 2026-11-09 · 图表课引入「A 画布模拟 + C Document Builder 基线」后的方法论沉淀。
> 回答两个讨论题：① 以后类似问题是否都能这样解？② 拿到一份数据，能否用 Python /
> Document Builder 直接解决真做图表的问题？（只分析不实现）

## 一、A+C+B 模式：什么时候可以复用

图表课遇到的问题结构是：**课程需要一个引擎没有的能力**。拆开看，任何能力缺口的
满足路径都有三层，成本与真实性递增：

| 层 | 做法 | 产出 | 代价 | 适用判据 |
| --- | --- | --- | --- | --- |
| A 模拟层 | 页面内用 JS/Canvas 画出来 | 课页动画 + 视频帧 | ~1 天 | 教学核心是**看懂过程**，不是对象真实性 |
| C 基线层 | Document Builder / 脚本生成真文件 | xlsx 真对象（QC 对照） | ~半天 | 需要**验收基准**或"真东西长什么样" |
| B 真引擎层 | Docker docserver + 引擎实现 | 浏览器内交互真对象 | 1-2 天/能力 | 教学核心是**操作真软件**（如透视表拖拽） |

**复用判据（后面遇到类似问题先过这三问）：**

1. 学习者要的是"理解概念"还是"会操作真软件"？前者 A 即可，后者必须 B。
2. 验收断言能不能在 A 层完成（数据序列/渲染存在性）？能则 C 可缓，不能则 C 补基准。
3. 该能力课程量有多大？≥3 门课值得建 B；1-2 门课 A+C 封顶。

**已映射的例子：**

| 能力缺口 | A | C | B |
| --- | --- | --- | --- |
| 图表（8 类） | chart-layer 画布 ✅ | chartref/Document Builder ✅ | #17 docserver（缓行） |
| 动态数组 UNIQUE/FILTER 溢出 | 单值形态课回避 | 基线文件展示完整溢出 | #14/#17 |
| 数据透视表 | ✗（交互是教学本体）| 基线透视文件 | #17（必须 B） |

结论：**不是所有问题都能 A+C**——判据第 1 问就挡住了透视表（拖拽交互是教学本体）。
但「视觉演示型」能力（图表/格式/条件样式/排序筛选动画）全部适用 A+C。

## 二、「拿到一份数据 → 直接出一套图表」的自动化分析

问题：用户给一份 CSV/数据，能否用 Python 或 Document Builder 自动完成
"选图 → 真图表 → 教学内容"？分层看：

### 能自动化的（机械部分）

| 环节 | Python 路线 | Document Builder 路线 | 判断 |
| --- | --- | --- | --- |
| 读数据/推断列型 | pandas（强） | 脚本内循环（弱） | Python 胜 |
| 规则选图 | 列型 → 图型映射表（时间序列→折线、类别+数值→柱形、两数值→散点…） | 同表可移植 | 都行，规则是现成的（docs/excel/02-charts 选型表就是规则源） |
| 生成真图表文件 | openpyxl/xlsxwriter（能建真 chart 对象） | AddChart（同能力） | **平手**——两者都能产出"打开 Excel 就有真图"的 xlsx |
| 生成 PNG 图 | matplotlib（强） | ✗ | Python 胜（但要视频帧时 render-video 已有 DOM 截帧路线） |
| 契约生成 | 两者都只是模板填空 | 同 | 都行（仓库现有脚本风格是零依赖 JS，倾向 JS 统一） |

### 不能自动化的（教学部分）

- **口径与边界**：哪个字段算"销售额"、异常行怎么处理、结论要不要带边界——
  docs/excel 的品质恰恰在这些"人定的口径"上，规则化会退化成模板味文案。
- **读图结论**：「6 月达到 2190，连续第三个月上升」这种一句话结论是教学内容本体，
  自动生成=默认摘要，可作草稿但必须人工过。
- **选图的意图层**：规则选图给"默认图"，但"这个问题该用什么图"是教学点本身
  （02-charts 全部 8 篇都在教这个），不能跳过。

### 结论（写档不实现）

1. **真做图表文件**（给人用，不是给课用）：Python（pandas+openpyxl）或 Document
   Builder 都完全可行，一次性脚本半天内可交付。选型规则直接取自 docs/excel/02-charts。
2. **产图表课**（本仓库流水线）：契约的 data/chart/summary 必须人工定稿（口径+结论），
   自动化只能到"契约草稿"为止——即转写脚本（批量二规划的 convert-md 同级），
   不建议全自动。
3. **产品化想法**（用户丢数据→出可分享图表报告）：独立于教程流水线的一个小工具
   （Python 更合适），与课程生产解耦。若要做，单独立项，不混入本仓库流水线。
