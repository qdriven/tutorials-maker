# 整体构建方式

> Excel Interaction 项目的构建方法论：**任务分解模式**（怎么拆）、**记录保存方式**（怎么记）、**验证保存方式**（怎么验）。所有 phase / task 的目录与文档都按本文约定组织；偏离约定前先改本文。

## 1. 任务分解模式

### 三层分解：项目 → phase → task

```
项目（excel-interaction）
 └─ phase（＝ build-checklist 的一个阶段，一个 phase 一个目录）
     └─ task（可独立执行的最小交付单元，一个 task 一个目录）
         └─ 三件套：task.md（计划）/ verify.md（证据）/ output.md（交接）
```

- **phase**：构建的一个阶段（phase-0 环境配置 … phase-8 记录收尾），与
  [excel-animation 的 build-checklist](../../excel-animation/docs/build-checklist.md) 的阶段一一对应。
  phase 目录下 `README.md` 说明「这个 phase 做什么」，`tasks/` 放任务。
- **task**：**可单独执行**——不依赖其他 task 的未完成产物，或依赖已在 task.md 显式声明（"前置"）。
  一个 task 是一次可验证的交付，粒度控制在**半天以内**。
- **task 三件套**：
  | 文件 | 角色 | 何时写 |
  | --- | --- | --- |
  | `task.md` | 计划：做什么、功能定义、**验证点** | 执行**前**（验证点先于动手） |
  | `verify.md` | 证据：逐验证点的执行记录 | 执行**后** |
  | `output.md` | 交接：产出什么、什么功能完成的、要点（hand-off） | 完成**后** |

### 划分原则

1. **单一职责**：一个 task 只交付一件事（如"装 ffmpeg"不与"TTS"混在一起）。
2. **验证点前置**：task.md 先定义"做到什么算完成"，再动手——验证点是验收合同。
3. **依赖显式**：前置 task 在 task.md 写明；能并行的 task 不设依赖。
4. **失败可退**：task 做砸只回滚本 task 的产出，不影响其他 task。

## 2. 记录保存方式

### 分工：计划 / 证据 / 交接 / 流水

| 载体 | 记什么 | 修改纪律 |
| --- | --- | --- |
| `task.md` | 做什么、功能、验证点 | 执行前定稿；执行中变更须在 index-log 记一笔 |
| `verify.md` | 验证点 × 命令 × 实际输出 × 结论 | 只追加，不覆盖历史 |
| `output.md` | 产出清单、完成功能、要点（hand-off 文档） | 完成后写一次，后续变更另记 |
| `docs/projects/index-log.md` | **执行流水**：每次执行/改动一条，按实践顺序 | **append-only**，错了补更正条目，不删旧条 |

### index-log 条目格式

```
## <日期> · #<序号> · <一句话标题>
- 范围: phase-X / task-XX（或"项目级"）
- 动作: 做了什么（改动/执行/修正）
- 要点: 改动任务要点日志——为什么这么做、影响什么
- 文档索引: 本次涉及的文档清单（相对链接）
```

### 三条纪律

1. **按实践顺序**（不是重要性、不是目录序）——流水还原"当时发生了什么"。
2. **追加不修改**——历史错了补"更正"条目；流水可信度来自不可变。
3. **同步写**——执行完立即记；隔天补记的信息量会掉一半。

## 3. 验证保存方式

### verify.md 逐验证点记录

每个 task.md 里的验证点在 verify.md 中占一节，四要素齐全：

```
### <验证点名称>
- 命令: <可复制重跑的命令>
- 实际输出: <关键行原文；长输出摘要 + 指向完整输出的路径>
- 结论: PASS / FAIL / SKIP（附一句原因）
```

### 规则

1. **数字说话**：版本号、路径、退出码、耗时——"能用"不算数，"v24.15.0 + exit 0"才算数。
2. **FAIL 也记**：失败的验证点 + 处置 + 是否转入遗留——坑位清单从这里长出来。
3. **可复现**：任何人拿着「命令」栏能在自己机器重跑；环境差异写在「实际输出」。
4. **完成判据**：task.md 的验证点**全部**有 verify.md 记录且结论 PASS（或有据的 SKIP）
   → 才写 output.md → 在 index-log 追加一条。

### 与「记录保存」的边界

verify.md 记**验证这件事本身**（检查了什么、结果如何）；index-log 记**执行这件事本身**
（什么时候做了什么改动）。同一动作前者留下证据、后者留下流水，互相链接但不互相替代。
